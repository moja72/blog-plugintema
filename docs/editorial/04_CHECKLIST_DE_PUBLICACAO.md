# PluginTema — Checklist de Publicação

> Este arquivo define a verificação final obrigatória antes de publicar ou atualizar qualquer artigo do Blog PluginTema.
>
> Ele deve ser usado em conjunto com:
>
> - `VOZ_EDITORIAL.md`
> - `POSICIONAMENTO_EDITORIAL.md`
> - `ESTRUTURA_DE_ARTIGOS.md`
> - `REGRAS_DE_PESQUISA.md`
> - `POLITICA_EDITORIAL.md`
> - `DIRETRIZES_DE_SEO.md`
> - `REVIEWS_E_COMPARATIVOS.md`
> - `TERMINOLOGIA_WORDPRESS.md`
> - `ESTILO_DE_IMAGENS.md`
>
> O objetivo deste checklist não é reescrever todas as regras editoriais. É funcionar como a última barreira antes de o conteúdo ir ao ar.

---

# 1. Regra principal

Um artigo não está pronto apenas porque está escrito.

Ele está pronto quando:

- está correto;
- está atualizado;
- tem uma função clara;
- interpreta o assunto;
- respeita a voz PluginTema;
- diferencia fato de opinião;
- ajuda o leitor a tomar uma decisão;
- não promete mais do que consegue provar;
- está tecnicamente e visualmente pronto para publicação.

---

# 2. Níveis de verificação

Use três níveis.

## 🔴 Obrigatório

Se falhar, **não publicar**.

## 🟡 Recomendado

Pode não bloquear a publicação, mas deve ser corrigido sempre que possível.

## 🟢 Contextual

Aplicar quando o tipo de artigo exigir.

---

# 3. Identidade do artigo

## 🔴 Obrigatório

- [ ] Está claro qual pergunta principal o artigo responde?
- [ ] Está claro para quem esse artigo foi escrito?
- [ ] Existe uma razão real para esse conteúdo existir?
- [ ] O artigo oferece algo além de repetir documentação, changelog, release ou página comercial?
- [ ] O leitor consegue entender por que o assunto importa?
- [ ] O artigo leva a alguma conclusão, orientação ou próximo passo?

Se não conseguimos responder claramente a essas perguntas, o conteúdo ainda não está pronto.

---

# 4. Título

## 🔴 Obrigatório

- [ ] O título descreve corretamente o conteúdo?
- [ ] O título deixa claro o assunto principal?
- [ ] O artigo realmente entrega o que o título promete?
- [ ] Não existe clickbait vazio?
- [ ] Não existe urgência falsa?
- [ ] Números, versões, datas e nomes presentes no título foram confirmados?

## 🟡 Recomendado

- [ ] O benefício, impacto ou decisão está perceptível no título?
- [ ] O título é específico o suficiente para não servir para qualquer outro artigo?
- [ ] É possível remover alguma palavra sem perder significado?
- [ ] A palavra-chave principal aparece naturalmente, quando relevante?

---

# 5. Introdução

## 🔴 Obrigatório

- [ ] A introdução chega ao assunto rapidamente?
- [ ] Não começa com uma definição genérica de WordPress, internet, tecnologia ou mercado?
- [ ] Não repete simplesmente o título?
- [ ] Não contém afirmações importantes sem sustentação?
- [ ] O leitor entende por que deve continuar lendo?

## 🟡 Recomendado

- [ ] A introdução tem entre 1 e 4 parágrafos na maioria dos casos?
- [ ] Existe algum parágrafo que pode ser removido sem perder informação?
- [ ] A introdução antecipa o principal ponto do artigo quando isso melhora a leitura?
- [ ] A voz já soa como PluginTema desde o início?

---

# 6. Resumo rápido

## 🟢 Contextual

Para artigos longos, técnicos, análises, atualizações ou comparativos:

- [ ] Um resumo rápido ajudaria o leitor?
- [ ] O resumo entrega informação real?
- [ ] Ele evita repetir a introdução?
- [ ] É possível entender a conclusão principal apenas por ele?
- [ ] O resumo deixa claro quando algo ainda é hipótese ou interpretação?

---

# 7. Estrutura

## 🔴 Obrigatório

- [ ] Existe somente um H1?
- [ ] H2, H3 e H4 seguem uma hierarquia semântica?
- [ ] Nenhum heading existe apenas para “encher” o sumário?
- [ ] As seções aparecem em uma ordem lógica?
- [ ] Não existem seções duplicadas?
- [ ] A conclusão realmente conclui o artigo?

## 🟡 Recomendado

- [ ] Os headings são informativos?
- [ ] Evitamos headings genéricos como “Introdução”, “Informações importantes” e “Outros pontos”?
- [ ] O primeiro parágrafo de cada seção entra no assunto sem preparação desnecessária?
- [ ] O artigo continua compreensível para quem pula diretamente para um H2?
- [ ] O sumário “Neste artigo” reflete a estrutura real?

---

# 8. Numeração do sumário

## 🟢 Contextual

Quando houver sumário hierárquico:

- [ ] H2 = 1, 2, 3...
- [ ] H3 = 1.1, 1.2, 1.3...
- [ ] H4 = 1.1.1, 1.1.2...
- [ ] A numeração acompanha corretamente a hierarquia?
- [ ] Nenhum nível foi pulado sem necessidade?

---

# 9. Qualidade de cada seção

Antes de manter uma seção, perguntar:

> **E daí?**

## 🔴 Obrigatório

Cada seção importante deve fazer pelo menos uma destas coisas:

- [ ] explicar o que mudou;
- [ ] explicar como funciona;
- [ ] oferecer contexto;
- [ ] explicar impacto;
- [ ] mostrar para quem aquilo importa;
- [ ] apontar problema ou limitação;
- [ ] comparar alternativas;
- [ ] recomendar uma ação.

Se não fizer nenhuma delas, considerar remover.

# 10. Fato, observação e opinião

## 🔴 Obrigatório

- [ ] Resultados de testes estão apresentados como observações daquele ambiente?
- [ ] Opiniões estão identificadas como interpretação quando necessário?
- [ ] Nenhuma preferência pessoal foi transformada em fato?
- [ ] Nenhum dado de fabricante foi repetido como verdade independente sem verificação?
- [ ] Previsões, roadmaps e rumores estão escritos com o grau correto de incerteza?

# 11. Opinião editorial

## 🔴 Obrigatório

Quando houver opinião:

- [ ] Existe argumento por trás dela?
- [ ] Existe evidência, teste, experiência, fonte ou contexto?
- [ ] A conclusão não depende apenas de gosto pessoal?
- [ ] A crítica é dirigida à decisão, produto ou implementação — não a ataques pessoais?

## 🟡 Recomendado

- [ ] O texto realmente interpreta o assunto ou apenas descreve?
- [ ] Existe algum ponto em que a PluginTema deveria assumir posição com mais clareza?
- [ ] Estamos evitando neutralidade artificial?
- [ ] A opinião ajuda o leitor a decidir?

# 12. Primeira pessoa

## 🔴 Obrigatório

Antes de usar “eu”, confirmar:

- [ ] O autor realmente testou, observou ou viveu aquilo?
- [ ] A frase representa experiência ou julgamento real?
- [ ] Não estamos inventando experiência pessoal?

Antes de usar “nós”, confirmar:

- [ ] A afirmação realmente representa a PluginTema?
- [ ] O teste foi realizado pela PluginTema ou equipe?
- [ ] Não estamos usando “nós” apenas para dar falsa autoridade?

## 🟡 Recomendado

- [ ] Um fato objetivo poderia ser escrito sem “eu acho”?
- [ ] O uso de primeira pessoa está proporcional ao tipo de artigo?

Referência:

| Tipo | “eu” | “nós” |
|---|---|---|
| Notícia | baixo | baixo |
| Tutorial | baixo | moderado |
| Atualização | baixo | moderado |
| Análise | moderado | moderado |
| Review | alto | moderado |
| Comparativo | moderado | moderado |
| Opinião | alto | moderado |
| PluginTema Labs | alto | alto |

# 14. Palavras e construções a revisar

Pesquisar no texto e avaliar se realmente são necessárias:

- [ ] “vale ressaltar”
- [ ] “faz-se necessário”
- [ ] “desta forma”
- [ ] “neste sentido”
- [ ] “consequentemente”
- [ ] “realizar a utilização”
- [ ] “implementação da solução”
- [ ] “supracitado”
- [ ] “revolucionário”
- [ ] “game changer”
- [ ] “incrível”
- [ ] “o melhor” sem contexto
- [ ] “obrigatório” sem sustentação
- [ ] “sempre”
- [ ] “nunca” quando a afirmação não é absoluta
- [ ] “100%” sem evidência

Substituir quando houver alternativa mais natural e precisa.

## 🔴 Obrigatório

Pesquisar por ideias repetidas:

- [ ] A introdução repete o primeiro H2?
- [ ] O resumo repete a introdução?
- [ ] Dois H2 dizem essencialmente a mesma coisa?
- [ ] A conclusão reconta o artigo inteiro?
- [ ] A mesma recomendação aparece várias vezes sem necessidade?
- [ ] O mesmo adjetivo está sendo usado repetidamente?

---

# 47. Frases genéricas de IA

## 🔴 Obrigatório

Remover ou reescrever frases como:

- [ ] “No cenário digital atual...”
- [ ] “Com a constante evolução da tecnologia...”
- [ ] “É importante destacar que...”
- [ ] “Este artigo explorará...”
- [ ] “Em um mundo cada vez mais conectado...”
- [ ] “Em conclusão, podemos observar...”
- [ ] “A escolha dependerá das suas necessidades específicas...” sem explicar quais necessidades.

Perguntar:

> Essa frase poderia estar em qualquer artigo de qualquer site?

Se sim, reescrever.

---

# 48. Conclusão

## 🔴 Obrigatório

- [ ] A conclusão responde à pergunta principal?
- [ ] Existe recomendação quando o tema pede uma?
- [ ] Está claro quem deve agir?
- [ ] Está claro quem pode esperar?
- [ ] Existe alguma ressalva essencial?
- [ ] A conclusão não introduz fatos importantes que deveriam estar no corpo?
- [ ] Não começa automaticamente com “Em conclusão”?

# 49. CTA

## 🟢 Contextual

- [ ] O artigo realmente precisa de CTA?
- [ ] O CTA tem relação com o tema?
- [ ] Não existe venda forçada?
- [ ] Há um próximo artigo natural?
- [ ] Comentar, salvar, testar ou acompanhar seria mais útil que vender?
- [ ] Quando comercial, o CTA continua coerente com a análise?

# 50. Revisão técnica final

## 🔴 Obrigatório

Antes de publicar:

- [ ] Todos os links funcionam?
- [ ] Todas as imagens carregam?
- [ ] Vídeos e embeds funcionam?
- [ ] Tabelas não quebram?
- [ ] Blocos de código estão formatados?
- [ ] Headings aparecem corretamente no sumário?
- [ ] Âncoras funcionam?
- [ ] O artigo está legível em mobile?
- [ ] Não existem trechos duplicados por erro de edição?
- [ ] Não ficaram observações internas, prompts ou placeholders no texto?

# 52. Revisão de credibilidade

Antes de publicar, perguntar:

- [ ] Existe alguma frase que eu não conseguiria defender se o leitor perguntasse “qual é a fonte?”
- [ ] Existe alguma opinião apresentada como certeza?
- [ ] Existe alguma conclusão mais forte do que os dados permitem?
- [ ] Estamos omitindo uma limitação que mudaria a decisão do leitor?
- [ ] Existe conflito de interesse relevante?
- [ ] Estamos vendendo algo que influencia indevidamente a análise?
- [ ] Existe alguma informação que sabemos estar desatualizada?

Se alguma resposta for “sim”, corrigir antes de publicar.

# 53. Revisão de utilidade

Perguntar:

- [ ] O leitor sabe mais depois de ler?
- [ ] O leitor entende o impacto?
- [ ] O leitor sabe o que fazer?
- [ ] Existe uma recomendação útil?
- [ ] O artigo economiza tempo do leitor?
- [ ] Ele ajuda a evitar algum erro?
- [ ] Há informação prática suficiente?

# 54. Teste da PluginTema

Antes de apertar “Publicar”, responder:

1. **O que aconteceu?**
2. **O que isso muda na prática?**
3. **Por que o leitor deveria se importar?**
4. **Para quem isso é relevante?**
5. **Qual é a nossa interpretação?**
6. **O que recomendamos fazer?**

Se o artigo não consegue responder às perguntas aplicáveis, revisar.

---

# 55. Teste do “e daí?”

Escolha os três principais fatos do artigo e pergunte:

> **E daí?**

- [ ] O texto explica a consequência do primeiro?
- [ ] O texto explica a consequência do segundo?
- [ ] O texto explica a consequência do terceiro?

Se não existe consequência relevante, reduzir o destaque daquele fato.

---

# 56. Teste do “para quem?”

Para cada recomendação importante:

- [ ] Está claro para qual perfil ela vale?
- [ ] Existe algum cenário em que a recomendação mudaria?
- [ ] Esse cenário foi mencionado quando relevante?

Evitar recomendações universais sem necessidade.

---

# 57. Teste do custo oculto

Quando o artigo recomendar uma solução:

- [ ] Consideramos performance?
- [ ] Consideramos manutenção?
- [ ] Consideramos preço e renovação?
- [ ] Consideramos curva de aprendizado?
- [ ] Consideramos dependência?
- [ ] Consideramos migração?
- [ ] Consideramos suporte?
- [ ] Consideramos privacidade?
- [ ] Consideramos infraestrutura?

Nem todos serão relevantes em todos os artigos.

---

# 58. Teste da leitura parcial

Verificar separadamente:

- [ ] título + introdução fazem sentido sozinhos?
- [ ] resumo rápido faz sentido sozinho?
- [ ] cada H2 principal pode ser consultado isoladamente?
- [ ] tabela pode ser entendida sem reler cinco parágrafos?
- [ ] conclusão responde à questão central?

---

# 59. Teste anti-documentação

Perguntar:

> Este texto acrescenta interpretação ou apenas reorganiza uma fonte oficial?

Se apenas reorganiza:

- [ ] acrescentar impacto;
- [ ] acrescentar contexto;
- [ ] acrescentar experiência;
- [ ] acrescentar contraponto;
- [ ] acrescentar recomendação.

Informar não é suficiente.

A PluginTema deve interpretar.

---

# 60. Teste anti-hype

Pesquisar afirmações fortes.

Para cada uma:

- [ ] Existe evidência?
- [ ] O adjetivo é necessário?
- [ ] A novidade realmente muda algo?
- [ ] Estamos confundindo anúncio com resultado?
- [ ] O entusiasmo é proporcional ao impacto?

## 🔴 Obrigatório

Confirmar:

- [ ] Não inventamos testes.
- [ ] Não inventamos experiência pessoal.
- [ ] Não inventamos consenso.
- [ ] Não inventamos números.
- [ ] Não inventamos fontes.
- [ ] Não inventamos limitações para parecer equilibrados.

# 62. Status final

Antes da publicação, marcar uma opção:

## ⛔ Não publicar

Existe erro factual, fonte insuficiente, problema técnico, conflito editorial ou item obrigatório pendente.

## ⚠️ Publicável com ajustes

O núcleo está correto, mas ainda existem melhorias recomendadas que devem ser feitas antes de ir ao ar sempre que possível.

## ✅ Pronto para publicar

Todos os itens obrigatórios aplicáveis foram atendidos e o artigo representa adequadamente a PluginTema.

Para revisões finais rápidas:

# 64. Regra final

> **Publicar não é terminar de escrever. É terminar de verificar.**

Um bom artigo da PluginTema deve ser correto o suficiente para gerar confiança, claro o suficiente para ser útil e opinativo o suficiente para não parecer apenas mais uma página repetindo o que já existe na internet.
