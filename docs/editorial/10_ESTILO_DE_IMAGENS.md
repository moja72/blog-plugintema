# PluginTema — Estilo de Imagens

> Este arquivo define a identidade visual das imagens editoriais do Blog PluginTema.
>
> Ele deve ser usado em conjunto com:
>
> - `VOZ_EDITORIAL.md`
> - `POSICIONAMENTO_EDITORIAL.md`
> - `ESTRUTURA_DE_ARTIGOS.md`
> - `CHECKLIST_DE_PUBLICACAO.md`
> - `DIRETRIZES_DE_SEO.md`
> - `TERMINOLOGIA_WORDPRESS.md`
> - `PROMPTS_DE_IMAGENS.md`
>
> Princípio central:
>
> **as imagens da PluginTema devem ser reconhecíveis antes mesmo de o leitor ver o logo.**

---

# 1. Personalidade visual

A identidade visual editorial da PluginTema deve transmitir:

- tecnologia;
- modernidade;
- energia;
- personalidade;
- clareza;
- irreverência controlada;
- precisão;
- cultura WordPress;
- linguagem visual contemporânea.

A estética principal é:

> **neo-brutalista digital, limpa, vetorial e editorial.**

Não deve parecer:

- banco de imagens corporativo;
- template genérico de blog;
- arte “tech futurista” cheia de neon;
- banner de promoção de marketplace;
- thumbnail de YouTube sensacionalista;
- arte excessivamente infantil;
- composição criada por IA sem direção de arte.

---

# 2. Princípio visual central

Toda imagem editorial deve responder visualmente a pelo menos uma destas funções:

1. representar o tema;
2. explicar uma ideia;
3. criar reconhecimento de marca;
4. ajudar o leitor a diferenciar conteúdos;
5. tornar um conceito técnico mais memorável;
6. contextualizar um produto, plataforma ou mudança.

Imagem não deve existir apenas para preencher espaço.

---

# 3. Linguagem neo-brutalista da PluginTema

A base visual deve utilizar, quando apropriado:

- contornos pretos marcantes;
- formas geométricas simples;
- sombras sólidas;
- cartões e objetos com volume gráfico;
- tipografia forte;
- contraste alto;
- cores de destaque bem definidas;
- formas com cantos levemente arredondados;
- composição aparentemente simples, mas cuidadosamente equilibrada.

---

# 4. Neo-brutalismo não significa desorganização

Evitar interpretar neo-brutalismo como:

- elementos jogados aleatoriamente;
- dezenas de cores;
- tipografia caótica;
- excesso de stickers;
- desalinhamento deliberado em tudo;
- estética propositalmente “feia”.

A PluginTema usa:

> **neo-brutalismo refinado.**

A imagem pode ser ousada sem parecer amadora.

---

# 5. Acabamento

O acabamento deve parecer:

- limpo;
- vetorial;
- preciso;
- nítido;
- editorial;
- intencional.

Evitar:

- bordas tremidas sem propósito;
- elementos mal recortados;
- perspectiva inconsistente;
- logos deformados;
- sombras borradas aleatoriamente;
- textos tortos sem função.

---

# 6. Formato principal das capas

Formato editorial principal:

> **horizontal, aproximadamente 2,05:1**

Esse formato deve ser priorizado para:

- imagem destacada;
- capa de artigo;
- cards de destaque;
- banners editoriais.

Exemplos aproximados:

- 1640 × 800;
- 1536 × 750;
- 1230 × 600.

A implementação final pode variar conforme o layout do blog, desde que preserve a relação visual.

---

# 7. Área segura

Elementos importantes não devem ficar colados nas bordas.

Manter uma área segura para:

- logos;
- textos;
- rostos;
- ícones principais;
- interfaces;
- produtos.

Pensar sempre em possíveis recortes para:

- cards;
- mobile;
- redes sociais;
- Open Graph.

---

# 8. Composição

Preferir composições com:

- 1 elemento principal;
- 2 a 5 elementos secundários;
- espaço negativo suficiente;
- leitura visual rápida.

Regra:

> o leitor deve entender a ideia principal da imagem em menos de dois segundos.

---

# 9. Ponto focal

Toda capa precisa de um ponto focal claro.

Pode ser:

- logo de produto;
- mascote;
- ícone;
- interface;
- objeto;
- palavra;
- número;
- símbolo;
- comparação A vs. B.

Evitar vários elementos com o mesmo peso visual.

---

# 10. Hierarquia visual

Ordem recomendada:

1. assunto principal;
2. contexto;
3. elementos decorativos;
4. marca.

O logo PluginTema não precisa ser sempre o maior elemento.

---

# 11. Assimetria controlada

Composição pode ser assimétrica.

Exemplo:

- objeto principal à esquerda;
- pequenos elementos à direita;
- grande área negativa;
- sombra deslocada.

A assimetria deve parecer intencional.

---

# 12. Bordas

Elementos principais podem usar:

- contorno preto espesso;
- linhas consistentes;
- bordas levemente arredondadas.

Evitar:

- bordas ultrafinas em arte neo-brutalista;
- muitos tipos de contorno na mesma imagem.

---

# 13. Espessura de contorno

Manter espessura visual consistente entre elementos do mesmo nível.

Elementos menores podem ter contorno proporcionalmente menor.

O contorno nunca deve desaparecer após redução da imagem.

---

# 14. Sombras

Sombras principais:

> **sólidas, duras e deslocadas.**

Preferir:

- offset lateral/diagonal;
- borda definida;
- sem blur ou com blur mínimo.

Evitar:

- drop shadow corporativo suave;
- glow;
- sombras realistas excessivas.

---

# 15. Direção das sombras

Escolher uma direção predominante por composição.

Exemplo:

- direita + baixo.

Não usar sombras apontando para lados diferentes em objetos semelhantes.

---

# 16. Profundidade

A profundidade deve vir principalmente de:

- sobreposição;
- contorno;
- sombra sólida;
- escala;
- deslocamento.

Não depender de efeitos 3D complexos.

---

# 17. Cantos

Preferir:

- retos;
- ou levemente arredondados.

Evitar cartões excessivamente arredondados com estética “SaaS genérico”.

---

# 18. Paleta

A paleta deve partir das cores oficiais da marca e dos tokens visuais do site.

Regra:

> **não inventar uma nova paleta a cada artigo.**

As cores exatas devem ser centralizadas nos tokens de design do projeto.

---

# 19. Estrutura de cor

Como padrão, uma imagem deve trabalhar com:

- 1 cor dominante;
- 1 cor secundária;
- preto;
- branco;
- opcionalmente 1 cor de destaque adicional.

Evitar arco-íris sem função.

---

# 20. Preto

O preto tem papel estrutural.

Usar para:

- contornos;
- tipografia;
- sombras;
- elementos de contraste;
- fundo em determinadas artes.

O preto reforça a identidade neo-brutalista.

---

# 21. Branco

O branco deve funcionar como:

- respiro;
- contraste;
- área limpa;
- fundo;
- detalhe.

Não preencher toda área apenas porque existe espaço.

---

# 22. Cores de categoria

Categorias podem possuir cores secundárias próprias.

Exemplo conceitual:

- WordPress;
- Performance;
- SEO;
- Plugins;
- Temas;
- WooCommerce;
- Construtores;
- Segurança;
- PluginTema Labs.

Mas:

> a categoria altera o **acento**, não a identidade inteira.

Contorno, composição, sombra e linguagem permanecem PluginTema.

---

# 23. Sistema de categoria

Se forem definidas cores fixas por categoria, manter um único mapa central no projeto.

Exemplo estrutural:

```text
WordPress       → cor A
Performance     → cor B
SEO             → cor C
Plugins         → cor D
Temas           → cor E
WooCommerce     → cor F
Construtores    → cor G
Segurança       → cor H
PluginTema Labs → cor I
```

Não definir novas cores manualmente artigo por artigo.

---

# 24. PluginTema Labs

PluginTema Labs pode ter variação visual mais experimental.

Pode usar:

- diagramas;
- medições;
- elementos de laboratório;
- gráficos;
- terminais;
- setas;
- “experimentos” visuais;
- componentes desmontados;
- grids técnicos.

Mas continua dentro da identidade principal.

---

# 25. Tipografia nas imagens

Texto dentro da imagem deve ser exceção, não obrigação.

Preferir imagens que funcionem mesmo sem texto.

---

# 26. Quando usar texto

Texto visual faz sentido para:

- comparação;
- número de versão;
- palavra curta;
- conceito;
- identificação de A vs. B;
- pequenos labels;
- mensagens editoriais específicas.

---

# 27. Quando evitar texto

Evitar texto dentro da imagem quando:

- o título do artigo já aparece imediatamente ao lado;
- a informação seria repetida;
- a arte pode ser reutilizada;
- o texto ficará ilegível no mobile.

---

# 28. Quantidade de texto

Como padrão:

- 1 a 6 palavras principais;
- labels curtos;
- evitar frases longas.

A capa não deve virar cartaz.

---

# 29. Texto não deve repetir o título inteiro

Exemplo:

Título do artigo:

> WordPress 7.1: o que mudou e o que revisar antes de atualizar

Imagem:

> **7.1**

ou:

> **WORDPRESS 7.1**

Não repetir todo o título na arte.

---

# 30. Tipografia

Preferir tipografia:

- forte;
- limpa;
- moderna;
- altamente legível;
- coerente com a marca.

Evitar:

- fontes ornamentais;
- handwriting aleatória;
- tipografia futurista genérica;
- muitas famílias tipográficas.

---

# 31. Peso tipográfico

Textos principais podem usar:

- bold;
- extra bold;
- black.

Labels secundários:

- medium;
- semibold.

Evitar textos principais ultrafinos.

---

# 32. Caixa alta

Caixa alta é permitida para:

- labels;
- versões;
- palavras curtas;
- categorias.

Evitar títulos longos inteiros em caixa alta.

---

# 33. Logos de produtos

Quando o artigo for sobre um produto específico, o logo pode ser ponto focal.

Regras:

- não deformar;
- não redesenhar incorretamente;
- não mudar proporção;
- não inventar versão;
- não recolorir sem necessidade;
- manter legibilidade.

---

# 34. Logos oficiais

Sempre que possível:

- usar arquivo oficial;
- usar versão vetorial;
- respeitar guidelines da marca.

Não redesenhar um logo com IA quando o logo real estiver disponível.

---

# 35. Logo PluginTema

O logo PluginTema pode aparecer:

- como assinatura;
- elemento central em conteúdos institucionais;
- selo;
- sticker;
- elemento secundário.

Não precisa estar em toda capa se o próprio blog já oferece contexto de marca.

---

# 36. Tamanho do logo PluginTema

Quando usado como assinatura:

- discreto;
- visível;
- sem competir com o assunto.

Quando o artigo for institucional:

pode ser central.

---

# 37. WordPress

Ao representar WordPress:

- usar logo oficial quando a identificação da plataforma for importante;
- ou usar referências visuais ao editor, blocos e ecossistema.

Evitar transformar toda imagem de WordPress em:

> logo azul enorme no centro.

Buscar variedade.

---

# 38. WooCommerce

Mesmo princípio:

- logo quando relevante;
- elementos de loja;
- carrinho;
- checkout;
- produtos;
- painel.

Não depender sempre do logo.

---

# 39. Elementor, Bricks, Divi e outros

Para comparativos:

- tratar visualmente as marcas com peso semelhante;
- evitar favorecer uma com tamanho maior sem função;
- usar logos oficiais;
- evitar distorções.

---

# 40. Comparativos A vs. B

Formato recomendado:

- divisão visual clara;
- dois elementos de peso equivalente;
- contraste entre cores;
- elemento central de comparação.

Pode usar:

> VS

desde que não pareça thumbnail sensacionalista de YouTube.

---

# 41. Comparativos não precisam parecer batalha

Evitar:

- fogo;
- raios;
- socos;
- explosões;
- “morte” do concorrente;
- estética de luta.

A PluginTema compara.

Não transforma software em campeonato de torcida.

---

# 42. Reviews

Imagem de review pode destacar:

- produto;
- interface;
- ícones de recurso;
- elemento de avaliação.

Evitar colocar:

> 10/10

na arte antes que a metodologia editorial realmente use notas.

---

# 43. Notícias

Imagens de notícia podem ser mais simples.

Priorizar:

- evento;
- produto;
- versão;
- mudança.

Não exagerar dramatização.

---

# 44. Atualizações de versão

Versão pode ser elemento central.

Exemplo:

> **7.1**

com:

- logo;
- blocos;
- componentes relacionados às mudanças.

---

# 45. Segurança

Imagens de segurança devem evitar clichês exagerados.

Evitar automaticamente:

- hacker encapuzado;
- máscara;
- código verde;
- caveira;
- laptop escuro.

Preferir:

- cadeado;
- plugin;
- alerta;
- escudo;
- versões;
- painel;
- vulnerabilidade representada graficamente.

---

# 46. Performance

Evitar sempre usar:

- velocímetro;
- foguete;
- raio.

Podem aparecer ocasionalmente.

Alternativas:

- métricas;
- gráfico;
- cronômetro;
- waterfall;
- barras;
- Core Web Vitals;
- páginas “mais leves”.

---

# 47. SEO

Evitar toda arte de SEO ser:

- lupa;
- gráfico subindo;
- Google estilizado.

Pode usar:

- SERP;
- snippets;
- headings;
- estrutura;
- páginas;
- entidades;
- Search Console;
- sinais visuais de indexação.

---

# 48. Inteligência artificial

Evitar:

- cérebro neon;
- robô humanoide genérico;
- circuito azul brilhante;
- rosto holográfico.

Preferir:

- prompts;
- nós;
- texto;
- fluxos;
- automação;
- integração com WordPress;
- elementos abstratos coerentes com o design PluginTema.

---

# 49. Screenshots editoriais

Screenshots devem ser tratados como informação.

Usar quando:

- mostram interface;
- comprovam comportamento;
- orientam tutorial;
- demonstram resultado.

---

# 50. Screenshot limpo

Antes de publicar:

- recortar áreas irrelevantes;
- ocultar dados privados;
- remover distrações;
- garantir resolução;
- manter contexto suficiente.

---

# 51. Dados sensíveis

Ocultar:

- e-mail;
- telefone;
- nome de cliente;
- IP;
- token;
- chave;
- senha;
- endereço;
- dados financeiros;
- identificadores privados.

---

# 52. Anotações em screenshots

Permitidas:

- seta;
- caixa;
- círculo;
- highlight;
- numeração;
- label curto.

Usar o estilo visual PluginTema.

---

# 53. Contorno em screenshots

Screenshots podem ser colocados dentro de:

- cards com borda preta;
- sombra sólida;
- moldura simples.

Isso ajuda a integrar interface real à linguagem neo-brutalista.

---

# 54. Não falsificar screenshot

Nunca:

- inserir botão que não existe;
- alterar valor;
- modificar resultado;
- criar interface fictícia e apresentá-la como real.

Mockup deve ser identificado como mockup quando houver risco de confusão.

---

# 55. Screenshot desatualizado

Se a interface mudou significativamente:

atualizar a imagem.

Não manter screenshot antigo apenas porque ainda “dá para entender”.

---

# 56. Diagramas

Diagramas devem ser:

- simples;
- visuais;
- claros;
- lineares quando possível.

Usar:

- caixas;
- setas;
- ícones;
- cores de categoria;
- bordas pretas.

---

# 57. Diagramas técnicos

PluginTema Labs pode usar diagramas mais densos.

Mas toda relação deve permanecer legível.

Não criar arquitetura visual apenas para parecer complexa.

---

# 58. Gráficos

Gráficos devem priorizar:

- leitura;
- metodologia;
- comparação honesta.

Não aplicar neo-brutalismo de forma que prejudique precisão dos dados.

---

# 59. Gráficos editoriais

Podem usar:

- bordas;
- labels;
- fundo limpo;
- elementos de marca.

Mas eixos e valores precisam permanecer corretos.

---

# 60. Ícones

Preferir ícones:

- simples;
- vetoriais;
- de traço consistente;
- visualmente compatíveis.

Evitar misturar:

- outline;
- 3D;
- skeuomorphic;
- emoji;
- filled;

sem intenção.

---

# 61. Ícones por categoria

Categorias podem ter um símbolo principal.

Exemplos conceituais:

- Performance → métrica/velocidade;
- SEO → busca/estrutura;
- Segurança → escudo;
- Construtores → layout/blocos;
- PluginTema Labs → laboratório/experimento.

O símbolo deve ser simples o suficiente para funcionar pequeno.

---

# 62. Emojis

Emojis podem aparecer como recurso visual ocasional.

Não devem ser a base da identidade editorial.

Usar apenas quando:

- houver humor;
- contexto comunitário;
- reação;
- conteúdo específico.

---

# 63. Stickers

Stickers são parte permitida da estética.

Podem representar:

- logos;
- recursos;
- categorias;
- conceitos;
- pequenos objetos.

Mas:

> cada sticker precisa ter função visual.

Evitar “chuva de stickers”.

---

# 64. Quantidade de stickers

Como referência:

- 2 a 6 em composições normais;
- mais apenas em artes cujo conceito seja propositalmente “pack” ou coleção.

---

# 65. Rotação

Pequenas rotações são permitidas.

Usar com moderação.

Não girar todos os elementos.

---

# 66. Ilustrações de objetos

Preferir:

- formas simples;
- contorno preto;
- volume gráfico;
- poucos detalhes;
- expressão visual forte.

---

# 67. Pessoas

Quando houver pessoa ilustrada:

- preservar proporções naturais;
- usar estilização coerente;
- evitar estética de banco de imagens;
- evitar mãos e rostos deformados.

Se for pessoa real:

não alterar sua identidade de forma enganosa.

---

# 68. Personagens

Personagens podem ser usados para:

- humor;
- situações;
- educação;
- metáforas.

Mas não criar um personagem recorrente sem decidir formalmente que ele faz parte da marca.

---

# 69. Fotografia

Fotografia pode ser usada quando o conteúdo realmente pede.

Exemplos:

- evento;
- pessoa;
- produto físico;
- escritório;
- bastidores.

Não usar fotografia genérica apenas porque parece “profissional”.

---

# 70. Fotografia + neo-brutalismo

Quando houver foto real:

integrar por:

- recorte;
- moldura;
- contorno;
- sombra;
- stickers;
- labels.

Não aplicar efeitos que comprometam autenticidade documental.

---

# 71. Imagens geradas por IA

Permitidas para:

- ilustrações;
- metáforas;
- composições;
- objetos;
- fundos;
- conceitos.

Devem seguir o mesmo padrão visual.

---

# 72. IA não substitui assets oficiais

Se o artigo for sobre:

- logo;
- interface;
- produto;
- UI;
- screenshot;

preferir asset real.

Não pedir à IA para “recriar” interface oficial e apresentar como verdadeira.

---

# 73. Arte gerada deve passar por revisão

Verificar:

- logos;
- textos;
- dedos;
- símbolos;
- proporções;
- interfaces;
- ortografia;
- ícones;
- sombras;
- consistência.

Imagem bonita mas factual ou visualmente errada não deve ser publicada.

---

# 74. Texto gerado dentro de imagem

Geradores de imagem podem errar texto.

Para texto crítico:

- gerar arte sem o texto;
- adicionar texto posteriormente em ferramenta de design.

---

# 75. Fundo transparente

Quando o asset for destinado a:

- sticker;
- logo;
- objeto isolado;
- composição posterior;

usar **transparência real**.

Não aceitar:

- fundo quadriculado desenhado;
- falso alpha;
- halo branco.

---

# 76. PNG/WebP transparente

Verificar visualmente em:

- fundo branco;
- fundo preto;
- fundo colorido.

Isso revela halos e recortes ruins.

---

# 77. Fundos

Fundos possíveis:

- cor sólida;
- preto;
- branco;
- bloco de cor;
- composição geométrica simples.

Evitar:

- gradiente genérico;
- neon;
- textura excessiva;
- ruído sem função.

---

# 78. Gradientes

Não são proibidos.

Mas devem ser exceção.

Se usados:

- poucos tons;
- coerência de marca;
- papel secundário.

A estética principal continua sólida.

---

# 79. Texturas

Permitidas em pequena escala para:

- papel;
- grão;
- impressão;
- efeito editorial.

Não reduzir nitidez.

---

# 80. Espaço negativo

Espaço vazio é parte ativa da composição.

Não tentar preencher toda área.

---

# 81. Densidade visual

Conteúdo simples:

> imagem simples.

Conteúdo amplo:

> imagem pode ter mais elementos.

Não criar arte extremamente complexa para assunto simples.

---

# 82. Cards internos

Cards podem representar:

- plugin;
- recurso;
- versão;
- métrica.

Devem usar:

- borda;
- sombra;
- hierarquia.

---

# 83. Interfaces estilizadas

Pode existir uma versão editorial simplificada de uma interface quando ela for claramente ilustração.

Não deve ser confundida com screenshot real.

---

# 84. Imagens de listas

Para artigos “5 melhores...”, evitar:

- cinco logos alinhados sem direção.

Preferir:

- composição;
- hierarquia;
- agrupamento;
- objeto central.

---

# 85. Números

Números grandes funcionam bem para:

- versão;
- benchmark;
- lista;
- percentual.

Mas só usar quando o número for realmente central.

---

# 86. Badges

Badges podem ser usados para:

- NOVO;
- BETA;
- RC;
- TESTE;
- LABS;
- UPDATE.

Evitar excesso.

---

# 87. Badge de categoria

Pode existir um sistema consistente de badge de categoria.

Mas o badge não deve dominar a capa.

---

# 88. Setas

Setas são permitidas para:

- fluxo;
- comparação;
- atenção;
- antes/depois.

Evitar setas gigantes de clickbait.

---

# 89. Antes e depois

Usar quando houver mudança visual real.

Manter:

- mesma escala;
- mesmo enquadramento;
- mesma condição.

Não manipular para exagerar diferença.

---

# 90. Conteúdo de dados

Quando imagem representa dados:

- não inventar;
- não arredondar de forma enganosa;
- não alterar escala;
- não gerar valores visualmente.

---

# 91. Identidade entre artigos

Duas capas diferentes da PluginTema devem compartilhar:

- linguagem de contorno;
- sombras;
- tipografia;
- paleta;
- proporção;
- densidade;
- acabamento.

Não precisam ter o mesmo layout.

---

# 92. Evitar template visual rígido

Consistência não significa:

> mesmo banner com logo trocado.

Cada assunto pode ter composição própria.

---

# 93. Sistema, não template

A identidade deve funcionar como:

> **um conjunto de regras.**

Não como:

> uma única arte reutilizada.

---

# 94. Categorias visualmente diferentes

Categorias podem mudar:

- cor de acento;
- ícone;
- pequenos elementos;
- composição temática.

Mas não mudar:

- linguagem geral;
- acabamento;
- estrutura visual base.

---

# 95. Mobile

Toda capa deve continuar entendível em tamanho reduzido.

Teste mental:

> se a imagem tiver 320 px de largura, o assunto principal ainda está claro?

---

# 96. Texto no mobile

Se texto não puder ser lido pequeno:

- reduzir;
- remover;
- simplificar.

Não confiar que o usuário abrirá a imagem.

---

# 97. Contraste

Texto e elementos importantes devem ter contraste suficiente.

Evitar:

- texto claro em cor clara;
- preto em roxo muito escuro;
- labels minúsculos.

---

# 98. Acessibilidade

Imagem não deve ser a única forma de transmitir informação essencial.

Informação importante deve existir no texto do artigo.

---

# 99. Alt text

Alt text é tratado em `DIRETRIZES_DE_SEO.md`.

Regra visual:

> a imagem deve ser compreensível, mas não depender do alt para corrigir uma composição confusa.

---

# 100. Open Graph

A imagem destacada deve funcionar bem quando compartilhada.

Verificar:

- recorte;
- legibilidade;
- ponto focal;
- contraste.

---

# 101. Redes sociais

Se forem criadas versões específicas:

manter a mesma arte-base.

Adaptar composição.

Não simplesmente esticar a imagem horizontal para vertical.

---

# 102. Reutilização

Assets isolados podem ser reutilizados.

Exemplos:

- stickers;
- ícones;
- padrões;
- molduras;
- sombras;
- elementos de categoria.

Isso aumenta consistência.

---

# 103. Biblioteca visual

Manter, quando possível, uma biblioteca organizada de:

- logos;
- stickers;
- ícones;
- elementos de WordPress;
- elementos de WooCommerce;
- categorias;
- molduras;
- fundos;
- componentes.

---

# 104. Nome de arquivos

Preferir nomes descritivos.

Exemplo:

`wordpress-7-1-controles-responsivos.webp`

Evitar:

`banner-final-2-agora-vai.webp`

---

# 105. Versões

Durante produção, usar padrão interno.

Exemplo:

```text
wordpress-7-1-capa-v01
wordpress-7-1-capa-v02
wordpress-7-1-capa-final
```

Para arquivo publicado:

remover versão desnecessária.

---

# 106. Formatos

Preferir formatos adequados ao uso:

- SVG → ícones/logos vetoriais quando seguro;
- WebP/AVIF → imagens editoriais;
- PNG → transparência ou necessidade específica;
- JPEG → fotografia quando apropriado.

---

# 107. Compressão

Otimizar sem destruir:

- bordas;
- textos;
- logos;
- detalhes.

Arte vetorial sofre muito com compressão ruim.

---

# 108. Resolução

Gerar em resolução suficiente para:

- telas retina;
- cards;
- compartilhamento.

Redimensionar na entrega.

Não gerar arte pequena e depois ampliar.

---

# 109. Screenshots em alta densidade

Quando possível:

- capturar em resolução alta;
- reduzir depois.

Isso preserva texto.

---

# 110. O que evitar — estilo genérico de IA

Evitar sinais recorrentes de imagem genérica:

- objetos flutuando sem lógica;
- excesso de profundidade;
- luz cinematográfica dramática;
- 3D plástico;
- neon roxo/azul por padrão;
- circuitos;
- hologramas;
- detalhes aleatórios;
- perspectiva impossível.

---

# 111. O que evitar — SaaS genérico

Evitar:

- cards super arredondados;
- gradiente azul/roxo;
- ícones 3D fofos;
- blobs;
- glassmorphism por padrão;
- sombras suaves em excesso.

Isso não é a identidade PluginTema.

---

# 112. O que evitar — thumbnail de YouTube

Evitar:

- setas vermelhas enormes;
- círculos vermelhos;
- texto “CHOCANTE”;
- rosto exagerado;
- fogo;
- explosões;
- “VS” agressivo;
- dezenas de exclamações.

---

# 113. O que evitar — corporate stock

Evitar:

- executivo apertando mão;
- pessoa apontando para laptop;
- equipe sorrindo em escritório genérico;
- mão segurando celular;
- cadeado flutuante sobre teclado.

Só usar fotografia quando ela tiver contexto real.

---

# 114. O que evitar — excesso de logo

Não transformar toda imagem em:

> colagem de logos.

Logos são ferramentas de identificação.

Não a linguagem inteira.

---

# 115. O que evitar — repetição

Se as últimas cinco capas usaram:

- logo central;
- três stickers;
- fundo roxo;

a próxima deve buscar outra composição dentro do mesmo sistema.

---

# 116. O que evitar — texto demais

Se a arte precisa de um parágrafo para funcionar:

a composição está errada.

---

# 117. O que evitar — informação inventada

Não colocar:

- versão inexistente;
- número fictício;
- gráfico fictício;
- interface falsa;
- selo que não existe.

---

# 118. O que evitar — elementos sem função

Cada elemento deve responder:

> por que está aqui?

Se a resposta for apenas:

> para preencher espaço,

remover.

---

# 119. Teste de reconhecimento

Antes de aprovar:

> Se eu remover o logo PluginTema, esta imagem ainda poderia pertencer ao nosso blog?

Se a resposta for “não”:

a identidade está dependente demais da marca aplicada, e não do estilo.

---

# 120. Teste de assunto

Perguntar:

> Sem ler o título do artigo, consigo entender aproximadamente sobre o que é?

Se não:

revisar o ponto focal.

---

# 121. Teste de redução

Reduzir mentalmente ou realmente a imagem.

Verificar:

- ponto focal;
- logos;
- texto;
- contornos;
- contraste.

---

# 122. Teste de excesso

Perguntar:

> Posso remover 20% dos elementos e a imagem melhorar?

Se sim:

remover.

---

# 123. Teste de coerência

Verificar:

- mesma direção de sombra;
- mesma família de contorno;
- mesma lógica de perspectiva;
- mesmos níveis de arredondamento;
- mesma linguagem de ícones.

---

# 124. Teste de factualidade

Quando houver produto ou interface:

- [ ] logo correto;
- [ ] versão correta;
- [ ] interface correta;
- [ ] texto correto;
- [ ] recurso realmente existe;
- [ ] não há elemento inventado.

---

- [ ] formato horizontal adequado;
- [ ] ponto focal claro;
- [ ] leitura rápida;
- [ ] estética PluginTema;

- [ ] sombra consistente;

- [ ] funciona em Open Graph;

- [ ] não parece imagem genérica de IA.

---

# 126. Checklist de screenshot

- [ ] interface atual;
- [ ] resolução suficiente;
- [ ] corte adequado;
- [ ] dados sensíveis removidos;
- [ ] anotação clara;
- [ ] não houve alteração enganosa;
- [ ] contexto suficiente;
- [ ] estilo visual integrado ao blog.

---

# 127. Checklist de ilustração

- [ ] conceito claro;
- [ ] elementos coerentes;
- [ ] contorno;
- [ ] sombra;
- [ ] acabamento vetorial;
- [ ] composição equilibrada;
- [ ] sem detalhes aleatórios;
- [ ] sem clichê visual desnecessário;
- [ ] sem texto incorreto.

---

# 128. Checklist de imagem gerada por IA

- [ ] logos não foram inventados;
- [ ] texto está correto;
- [ ] não há artefatos;
- [ ] perspectiva faz sentido;
- [ ] mãos/rostos estão corretos quando houver;
- [ ] nenhuma interface falsa parece screenshot;
- [ ] fundo transparente é real quando solicitado;
- [ ] composição segue a identidade;
- [ ] não há elementos genéricos de “IA tech”.

---

# 129. Checklist de gráfico

- [ ] dado real;
- [ ] fonte;
- [ ] escala correta;
- [ ] labels legíveis;
- [ ] unidades;
- [ ] comparação justa;
- [ ] metodologia disponível;
- [ ] estética não compromete precisão.

---

# 130. Regra final

> **A imagem PluginTema deve parecer tecnologia com personalidade, não tecnologia genérica.**

A estética é forte, mas não barulhenta.

É jovem, mas não infantil.

É moderna, mas não segue qualquer tendência visual apenas porque está em alta.

É neo-brutalista, mas refinada.

O objetivo final é criar um sistema visual que permita variedade sem perder reconhecimento.
